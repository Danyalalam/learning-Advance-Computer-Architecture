DES example (1-20): keys 0 … 256−1, 2 CPUs each take half. Key = 255: sequential needs 255+1 tries, CPU 2 finds it on try 1 → speedup 255+1, efficiency ≈ 254. Key = 2: both need 3 tries → speedup 1.

Fair speedup (1-13): same hardware and software, similar conditions, and tseq from the fastest known sequential program, not the parallel one run on 1 CPU. Not objective (1-12): it depends on the programmer, compiler, compiler switches, OS, filesystem and time of day.

2 · The two laws

Amdahl (1967), fixed problem size:   speedup = 1 / ((1 − α) + α / N)  ·  N → ∞: speedup → 1 / (1 − α)  ·  time: tpar = T · ((1 − α) + α / N)
Gustafson-Barsis (1988), problem grows with N:   speedup = (1 − α) + N · α  ·  efficiency = (1 − α) / N + α ≥ α  ·  tseq = (1 − α)T + NαT
Wording in the questionLawα is a fraction of…
"A sequential application … x% must run sequentially … accelerate it"Amdahlthe sequential (1-CPU) run
"A parallel application running on N CPUs spends x% of its time sequentially"Gustafson-Barsisthe parallel (N-CPU) run

Amdahl, α = 0.9, N = 10: 1 / (0.1 + 0.09) = 5.26; limit 10.

Barlas 1.4: 20% sequential (α = 0.8), want 3× → 0.2 + 0.8/N = 1/3 → N = 6. Want 5× → limit is exactly 5 → impossible.

Gustafson, Barlas 1.8 (Sheet Task 1): 10 CPUs, 15% sequential (α = 0.85): 0.15 + 10 · 0.85 = 8.65 → one CPU must be 8.65× faster.

Both are wrong (1-37): they assume zero communication overhead. Lesson: there is room for optimism, and simple models predict performance before building.

Ants vs elephants (1-31, 1-32) and Barlas 1.6

CPU A is r = TB / TA times faster than B. NB cheap CPUs vs one A: speedup = 1 / ((1 − α) r + α r / NB); limit 1 / ((1 − α) r). The ants never win if r ≥ 1 / (1 − α) (α = 0.9, r = 10 → tie at best).

Machines with different CPUs → compare TIMES with tpar = T((1 − α) + α/N). Barlas 1.6, α = 0.95: X (4 CPUs, 1 h): 0.2875 h ≈ 17 min. Y (16 CPUs, 2 h): 2 · 0.109 = 0.219 h ≈ 13 min → buy Y.

D5 pipeline: M stages, N items (2-37 to 2-39)

General: ttotal = (stages before the slowest) + N · tslowest + (stages after); rate = N / ttotal; latency = t0 + … + tM−2. The slowest stage dominates.

Uniform stages t: total = (N + M − 1) · t · rate = N / ((N + M − 1) t) · latency = (M − 1) · t · speedup = N·M / (N + M − 1) ≈ M
M = 5, t = 2 ms, N = 100 → total 208 ms, latency 8 ms, speedup 4.81

6 · Program structure patterns (2-41 to 2-53)

GPLS (globally parallel, locally sequential): SPMD, MPMD, master-worker, map-reduce.
GSLP (globally sequential, locally parallel): fork/join, loop parallelism.

SPMD: one program; init → get unique ID (from 0; CUDA uses vector IDs) → run, path depends on ID → shut down.

MPMD: used when SPMD fails: memory too big for all nodes, or heterogeneous platforms. Same steps, different programs deployed. MPI supports both.

Master-worker: master hands out work, collects results, does I/O, talks to the user. Good for implicit load balancing; master can be a bottleneck → hierarchical version.

Map-reduce: master-worker variant (Google). Map = apply a function → partial results; reduce = combine them.

Fork/join: one parent thread spawns child tasks at run time; parent waits for children. OpenMP.

Loop parallelism: split loops via the loop variable; for migrating legacy code; limited scalability, low effort; OpenMP.

Quicksort (fork/join): extra tasks T(N) = N / THRES − 1. 220, THRES 210 → 1023.
