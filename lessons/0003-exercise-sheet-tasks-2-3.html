Warm-up: Barlas 1.6 again, new numbers

You struggled with this one, so here it is again with different numbers. The rule: when the CPUs differ, compute each machine's time with tpar = T · ((1 − α) + α / N), where T is that machine's single-CPU time. Then compare the times.

An application is 10% non-parallelizable. Machine X has 2 CPUs, each running it alone in 1 hour. How many minutes does X need?

α = 0.9. 60 min · (0.1 + 0.9 / 2) = 60 · 0.55 = 33 min.

Machine Y has 8 CPUs, each running the same application alone in 3 hours. How many minutes does Y need?

180 min · (0.1 + 0.9 / 8) = 180 · 0.2125 = 38.25 min. This time X wins: r = 3 is not far enough below 1 / (1 − α) = 10 to make up for only having 8 CPUs.

Task 2: when is a 1-D split better than a 2-D split?

The problem (slide 2-20). Heat diffusion on a 2-D surface, stored as an N × N grid of cells. In each time step every cell's new temperature is computed from its old value and its four direct neighbours (up, down, left, right). New to this? Do lesson 2b first. slide 2-20

The assumptions (slides 2-21 to 2-24). P compute nodes. tcomp is the cost of updating one cell; tcomm the cost of sending one data item; tstart the start-up latency of each message. Links are full-duplex, so a node sends and receives at the same time. Outer boundaries of the grid are ignored. slide 2-22

Step 1: costs of the 1-D split (vertical strips)

Each node gets a strip k = N / P columns wide and N rows tall, so k · N cells.

comp1D = k · N · tcomp = (N² / P) · tcomp

A strip has 2 neighbours, left and right. To each it sends one border column of N cells: one message costing tstart + tcomm · N.

comm1D = 2 · (tstart + tcomm · N)

Step 2: costs of the 2-D split (square blocks)

The grid is cut into √P × √P blocks, each k = N / √P cells wide, so k² = N² / P cells.

comp2D = k² · tcomp = (N² / P) · tcomp

A block has 4 neighbours. To each it sends one border of k cells.

comm2D = 4 · (tstart + tcomm · N / √P)

slides 2-23, 2-24

Step 3: the inequality

1-D is better when its total cost is smaller. The computing costs are identical, so they cancel:

comm1D + comp1D < comm2D + comp2D
⇔ 2tstart + 2tcommN < 4tstart + 4tcommN / √P
⇔ 2tcommN − 4tcommN / √P < 2tstart
⇔ tstart > tcomm · N · (1 − 2 / √P)

slide 2-25

What it means. 1-D sends 2 messages, 2-D sends 4, but the 2-D messages are shorter. If starting a message is expensive (large tstart), fewer messages win and 1-D is better. If sending data is expensive, shorter borders win and 2-D is better. Think of it as few large batches versus many small ones.

On the test, write all three steps: the four cost formulas with a one-line reason each, the cancellation of the computing costs, then the algebra. The final line alone shows the result, not the derivation the task asks for.

Practice: Task 2

Why can the computing costs be dropped from the inequality?

Both splits give each node the same number of cells, N² / P, so comp1D = comp2D and they cancel on both sides.

N = 100, P = 16, tstart = 10, tcomm = 1. What is comm1D?

2 · (10 + 1 · 100) = 220.

Same values. What is comm2D?

√16 = 4, so k = 100 / 4 = 25. 4 · (10 + 1 · 25) = 140. Here 2-D is better.

Keep N = 100, P = 16, tcomm = 1. Above which value of tstart does 1-D become the better choice?

tcomm · N · (1 − 2 / √P) = 1 · 100 · (1 − 2 / 4) = 50. Check at tstart = 50: comm1D = 300 and comm2D = 300, equal.

Task 3: the prefix-sum loops

3a, recursive data decomposition in two sentences. A sample answer built from slide 2-26:

A recursive data structure such as a tree, list or graph is broken down into its individual elements, and each element or group of elements is assigned to a separate compute node. The algorithm may have to be modified so that these operations can run concurrently, solving bigger subproblems from the results of smaller ones, as in dynamic programming. slide 2-26

3b to 3e, the code on slide 2-28, translated to Python. The pointer swapping just means "the new array becomes the old one for the next round". slide 2-28

step = 1
while step < N:                     # outer loop
    pos = 0
    while pos + step < N:           # inner loop
        S_new[pos + step] = S_old[pos] + S_old[pos + step]
        pos += 1
    S_old, S_new = S_new, S_old     # swap buffers
    step *= 2

Everything follows from two observations:

  • Inner loop: pos runs 0, 1, 2, … while pos < N − step, so it runs N − step times. With step = 1 that is N − 1; with step = 2 it is N − 2.
  • Outer loop: step takes the values 1, 2, 4, …, 2i while 2i < N. For N = 2k that is i = 0 … k − 1, so it runs lg N times.

3e, the total number of assignments, adds the inner counts over all outer passes (the same sum as on slide 2-33):

Σi=0…lgN−1 (N − 2i) = N · lg N − (2lgN − 1) = N · lg N − N + 1

The middle step uses the geometric sum 1 + 2 + 4 + … + 2k−1 = 2k − 1. Check with N = 4: step 1 gives 3, step 2 gives 2, total 5 = 4 · 2 − 4 + 1.

Practice: Task 3

Use N = 16. Trace it on paper if the formula feels shaky.

How many times does the inner loop run when step = 1?

N − step = 16 − 1 = 15.

How many times does it run when step = 2?

16 − 2 = 14.

How many times does the outer loop run?

step = 1, 2, 4, 8; at 16 the condition step < 16 fails. lg 16 = 4.

How many times is the assignment Snew[pos + step] = … executed in total?

15 + 14 + 12 + 8 = 49, and the formula gives 16 · 4 − 16 + 1 = 49.

Which expression gives that total for any N that is a power of 2?

Σ (N − 2i) for i = 0 … lg N − 1 is N lg N − (N − 1) = N lg N − N + 1.

The sequential prefix-sum on slide 2-27 needs N − 1 additions. What does that say about the alternative on slide 2-28?

Θ(N lg N) work against Θ(N): it does more work in total. It pays off only because each step's inner loop iterations are independent and can run on many CPUs at once, taking ⌈lg N⌉ parallel steps (slides 2-30, 2-31).
