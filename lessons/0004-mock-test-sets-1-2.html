Mock test

Twenty-four questions taken only from the slides and the seminar work, mixed together the way a real test mixes them. Treat it like the real thing: no formula sheet, pen and paper, one attempt per question.

Every explanation cites its slide. Anything you miss tells you which slides to reread tonight.

In Flynn's taxonomy, which class does a GPU belong to at the level of a single Streaming Multiprocessor?

Slide 1-5: GPUs follow SIMD at the level of the SM (NVidia) or SIMD unit (AMD). As a whole, multicore machines including GPUs are MIMD.

A sequential program is 95% parallelizable. According to Amdahl's law, what speedup does it reach on 20 CPUs?

1 / (0.05 + 0.95 / 20) = 1 / 0.0975 ≈ 10.26. Slide 1-28.

Which pair of properties does slide 1-7 give for GPUs, as opposed to CPUs?

Slide 1-7: GPUs have small caches, single-time use of data, big data volume, simple program logic and simple ALUs. Large caches, decoding and prediction hardware, and pipelined execution describe CPUs.

A parallel application on 32 CPUs spends 5% of its total time in sequential execution. What speedup does Gustafson-Barsis give?

α = 0.95: (1 − 0.95) + 32 · 0.95 = 0.05 + 30.4 = 30.45. The percentage is measured on the parallel run, so this is Gustafson-Barsis. Slide 1-34.

A sequential program takes 64 s. Its parallel version takes 6.4 s on 8 CPUs. What is the efficiency, in percent?

speedup = 64 / 6.4 = 10, efficiency = 10 / 8 = 1.25, so 125%. Speedup above N: this is super-linear speedup. Slides 1-14, 1-19.

DES brute force on 2 CPUs, keyspace split in half, secret key 255. What is the efficiency, approximately?

The sequential search needs 255 + 1 attempts; the second CPU finds the key on its first. Speedup = 255 + 1, efficiency = (255 + 1) / 2 ≈ 254. Slide 1-20.

Same setup, but the secret key is 2. What is the speedup?

The key lies in the first CPU's half. Both the sequential program and the first CPU try keys 0, 1, 2: three attempts each. Speedup = 3T / 3T = 1. The second CPU contributes nothing. Slide 1-20 asks exactly this.

One CPU solves a problem in 10 s. Four CPUs solve a problem four times as big in 12.5 s. What is the weak scaling efficiency, in percent?

tseq / t′par = 10 / 12.5 = 0.8, so 80%. N does not appear in the formula: the problem already grew N times. Slide 1-22.

Which kind of scalability do the slides call the most challenging to improve?

Slide 1-23: strong scaling efficiency (fixed problem, more CPUs) is the one most challenging to improve. It is the same as plain efficiency.

According to the experimentation guidelines, how many threads should a multicore measurement use?

Slide 1-27: threads and processes should not exceed the number of available hardware cores. Disable hyperthreading.

Which profiling technique modifies the program's code, usually requiring recompilation?

Slide 1-25: instrumentation modifies the code to collect information. Sampling interrupts the running program periodically to see which function is executing.

Which two PCAM steps are platform specific?

Slide 2-4: partitioning and communication are algorithm specific; agglomeration and mapping are platform specific.

PCAM agglomeration for a machine with 8 compute nodes: roughly how many groups does the rule of thumb suggest?

Slide 2-4: about one order of magnitude more groups than compute nodes, so about 8 · 10 = 80.

PCAM convolution example with a 3 × 3 kernel and one task per pixel. Using the count on slide 2-10 that leaves out each pixel's own value, what is totalComm for a 100 × 50 image?

totalComm = 8 · IMGX · IMGY = 8 · 100 · 50 = 40 000. Each pixel's task needs its 8 neighbours. Counting the pixel itself as well gives the slide's other figure, 9 · IMGX · IMGY.

Each video frame passes through decode, filter and encode stages, with different frames in different stages at once. Which decomposition pattern is this?

Slides 2-35, 2-36: a pipeline is an assembly line, with items flowing through stages that each apply one operation. Data flow, regular: D5.

Tasks decide only at run time which other tasks to send messages to. Which decomposition pattern fits?

Slide 2-40: D1 to D5 have a fixed communication flow. When tasks decide about communication at run time, event-based decomposition is needed.

A pipeline has M = 5 uniform stages of t = 2 ms each and processes N = 100 items. What is the total time, in ms?

(N + M − 1) · t = 104 · 2 = 208 ms. Slide 2-39.

Same pipeline. What is its speedup over doing all stages for every item one after another?

N · M / (N + M − 1) = 500 / 104 ≈ 4.81, close to M = 5. Slide 2-39.

Same pipeline. What is its latency, in ms?

(M − 1) · t = 4 · 2 = 8 ms: the time until all stages have input. Slides 2-37, 2-39.

Which category does the fork/join pattern belong to?

Slide 2-41: GSLP contains fork/join and loop parallelism. GPLS contains SPMD, MPMD, master-worker and map-reduce.

What weakness of the master-worker pattern do the slides name?

Slide 2-45: master-worker is good for implicit load balancing, but the master can be a bottleneck.

Parallel quicksort with fork/join: N = 220 items, THRES = 28. How many extra tasks are created?

T(N) = N / THRES − 1 = 212 − 1 = 4095. Slide 2-51.

According to the table on slide 2-53, which program structure pattern is not suitable for pipeline decomposition?

Slide 2-53: master-worker, map-reduce and loop parallelism have no tick in the pipeline column. SPMD, MPMD and fork/join support all six patterns.

Prefix-sum with the doubling algorithm on N − 1 CPUs, for N = 1024. What is the efficiency, in percent?

efficiency = 1 / ⌈lg N⌉ = 1 / 10, so 10%. Slide 2-31.
