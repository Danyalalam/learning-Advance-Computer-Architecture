Speedup, efficiency and Amdahl's law

After this lesson you can answer the most likely calculation question on the test: "how much faster does this program get on N CPUs?"

The setting

A sequential program runs on one CPU, one step after another. A parallel program splits its work across N CPUs (the slides also say cores or nodes) that run at the same time. You already do this: training on 4 GPUs instead of 1 is a parallel program.

The course measures a parallel program with wall-clock time only. Counting steps or big-O "has little to no benefit" here. slide 1-11

Two numbers: speedup and efficiency

Speedup · slide 1-11 speedup = tseqtpar

tseq is the time of the sequential program, tpar the time of the parallel one, both solving the same problem instance. Speedup tells you whether going parallel helped at all (speedup > 1).

Efficiency · slide 1-14 efficiency = speedupN = tseqN · tpar

Efficiency tells you what the speedup cost. Read it as the average share of time each CPU did useful work. If speedup = N, efficiency is 100%: that is linear speedup. slide 1-14

Fairness rule. tseq must come from the fastest known sequential program, run on the same hardware and software, not from the parallel program run on one CPU. Otherwise a slow baseline flatters your speedup. slide 1-13

Amdahl's law: the sequential part is the ceiling

Think of one training epoch that takes 100 s: 20 s of single-threaded data loading and 80 s of GPU compute. Add GPUs and the 80 s shrinks. The 20 s never does. Even with infinite GPUs the epoch takes 20 s, so you can never be more than 5 times faster.

Amdahl made that argument general. Take a program that needs time T on one CPU. A fraction α of it can be parallelized; the remaining 1 − α must stay sequential. On N CPUs, the parallel part takes αT / N and the sequential part still takes (1 − α)T.

Amdahl's law · slide 1-28 speedup = T(1 − α)T + αT / N = 1(1 − α) + α / N
With infinite CPUs · slide 1-29 limN → ∞ speedup = 11 − α
Watch the notation. In these slides α is the parallelizable part. Exercises often give the sequential part instead ("20% must run sequentially"). Then α = 0.8, not 0.2. Many other textbooks define the symbol the other way round.

The law assumes zero communication overhead and a parallel part that divides evenly among any number of CPUs, so it is an upper bound, not a prediction. slide 1-28

See it

Set α to 0.90 and drag N to 1024. The speedup stalls just under 10 while the efficiency collapses.

Practice

Use pen and paper, then type the answer. Decimals: two places are enough. Do not scroll back to the formulas unless you are stuck: recalling them from memory is what makes them stick.

A sequential program takes 120 s. Its parallel version takes 30 s on 8 CPUs. What is the speedup?

speedup = tseq / tpar = 120 / 30 = 4. The number of CPUs does not appear in the speedup.

Same program. What is its efficiency, in percent?

efficiency = speedup / N = 4 / 8 = 0.5, so 50%. On average each CPU did useful work half the time.

For a fair speedup figure, which program must tseq come from?

Slide 1-13: the sequential program should be the fastest known solution. A parallel program run on one CPU carries overhead that a good sequential program does not have, which would inflate the speedup.

A program has α = 0.9. According to Amdahl's law, what is the speedup on N = 10 CPUs?

1 / ((1 − 0.9) + 0.9 / 10) = 1 / (0.1 + 0.09) = 1 / 0.19 ≈ 5.26. Ten CPUs, barely half of them paying off.

A program has α = 0.75. What does Amdahl's law predict as N grows without limit?

The limit is 1 / (1 − α) = 1 / 0.25 = 4. The sequential quarter of the program remains however many CPUs you add.

The epoch from above: 100 s on one GPU, of which 20 s is sequential data loading. Under Amdahl's assumptions, what is the speedup on 4 GPUs?

The sequential part is 20%, so α = 0.8. speedup = 1 / (0.2 + 0.8 / 4) = 1 / 0.4 = 2.5. Check with times: 20 s + 80 s / 4 = 40 s, and 100 / 40 = 2.5.

Barlas exercise 1.4: an application with a 20% part that must run sequentially is to be accelerated three-fold. How many CPUs are required?

α = 0.8. Solve 1 / (0.2 + 0.8 / N) = 3: then 0.2 + 0.8 / N = 1/3, so 0.8 / N = 0.1333 and N = 6.

Barlas exercise 1.4, second half: the same application should now reach a speedup of 5. How many CPUs are required?

The limit is 1 / (1 − α) = 1 / 0.2 = 5. Solving 0.2 + 0.8 / N = 0.2 gives 0.8 / N = 0, which no finite N satisfies. A speedup of 5 is only approached, never reached.
