PCAM and the decomposition patterns

Slide set 1 asked how much faster a parallel program gets. Slide set 2 asks how to split a program into parallel pieces in the first place. After this lesson you can name the four PCAM steps, sort a problem into one of six patterns, and read the setup of Task 2.

You already know this from ML

When a model is too slow on one GPU, you choose how to split it:

  • Data parallel: every GPU gets a different slice of the batch. You split the data.
  • Pipeline parallel: GPU 1 runs layers 1 to 10, GPU 2 layers 11 to 20, and batches flow through. You split the flow.
  • Either way, the GPUs must exchange gradients or activations. That communication costs time and decides whether the split pays off.

Slide set 2 is the general theory behind those choices.

Words you need

TermMeaning here
TaskA piece of the computation that can run on its own CPU.
NodeA compute node: one CPU or core that runs tasks.
CommunicationData one task needs from another. Within a node it is cheap; between nodes it costs time.
Task dependency graphTasks drawn as circles, with an arrow wherever data flows from one task to another.

PCAM: four steps to design a parallel program

Ian Foster's method, from 1995. slides 2-3, 2-4

StepWhat you doDepends on
PartitioningBreak the computation into as many small tasks as possible, by function (functional decomposition) or by data (domain decomposition).the algorithm
CommunicationWork out how much data flows between those tasks. Steps 1 and 2 together give the task dependency graph.
AgglomerationGroup tasks to cut communication. Rule of thumb: about ten times more groups than nodes.the platform
MappingAssign groups to nodes so the load is balanced and communication is low.

Steps 1 and 2 split as finely as possible. Steps 3 and 4 then group the pieces back up to fit the machine you actually have.

The slides' example: image convolution

You know convolution from CNNs. Each output pixel is a weighted sum of a 3 × 3 neighbourhood of input pixels, using the kernel weights. A blur kernel has all nine weights equal to 1/9. slides 2-5 to 2-8

  1. Partitioning: one task per output pixel, so IMGX · IMGY tasks. This is what "unrolling the two outer loops" on slide 2-8 means: every loop iteration becomes its own task. slide 2-9
  2. Communication: each pixel task needs its 8 neighbours' values, so totalComm = 8 · IMGX · IMGY. Counting the pixel's own value as well, as the code does, gives 9 · IMGX · IMGY. slide 2-10
  3. Agglomeration: group the pixels into M vertical strips, IMGX / M columns wide. Inside a strip, neighbours are on the same core and communicate for free. Only the strip edges talk: 2 · (M − 1) one-way transfers of one column (IMGY pixels) each. slide 2-11
  4. Mapping: one strip per core.

Agglomeration shrank communication from about 8 values per pixel to two columns per strip boundary. That is the whole point of the step.

The six decomposition patterns

PCAM is general but a lot of work. Decomposition patterns are ready-made answers to "which parts can run at the same time?" Pick the row by what you split, and the column by its shape. slide 2-12

You split…Linear / regularRecursive / irregular
the functionsD1 Task parallelismD2 Divide and conquer
the dataD3 Geometric decompositionD4 Recursive data decomposition
the flow of dataD5 PipelineD6 Event-based coordination

D1 Task parallelism · slides 2-13, 2-14

The tasks are fixed in advance (a priori). The slides' example is a game loop: read input, draw the screen, play sounds and run the AI, each as its own task. A barrier after each function makes every task wait until all four have finished the current frame, so no task races ahead into the next one. Weakness: four functions give at most four tasks, so it does not scale strongly.

D2 Divide and conquer · slides 2-15 to 2-19

Split a problem into subproblems, solve them recursively, merge the results. In parallel, each subproblem becomes a new task, but only while it is "big enough for a split"; small ones are solved sequentially. Example: mergesort, whose call graph is a tree of tasks.

D3 Geometric decomposition · slides 2-20 to 2-25

The data sits in a regular structure such as an array or matrix. Cut it along one or more dimensions and give each piece to a task. Lesson 3's Task 2 is about exactly this, so the details are below.

D4 Recursive data decomposition · slides 2-26 to 2-34

For trees, lists and graphs, which do not cut neatly. Break the structure into single elements, one per node, often after changing the algorithm. Example: prefix-sum, in lesson 3's Task 3.

D5 Pipeline · slides 2-35 to 2-39

An assembly line: each item passes through stages, and different items are in different stages at once. Total time is set by the slowest stage.

D6 Event-based coordination · slide 2-40

D1 to D5 have a communication flow known in advance. When tasks decide only at run time whom to message, you need events: time-stamped messages such as requests, responses or state changes.

D3 up close: the setup of Task 2

The problem. A metal plate is modelled as an N × N grid of cells, each holding a temperature. In every time step each cell's new temperature is computed from its old value and its four direct neighbours: up, down, left and right. slide 2-20

u′[i, j] = u[i, j] + δt · (u[i−1, j] + u[i+1, j] + u[i, j−1] + u[i, j+1] − 4u[i, j]) / h²

You do not need to understand the physics. What matters is that each cell reads its four neighbours, so a cell on the edge of a node's region needs values that live on another node.

Two ways to cut the grid among P nodes. slide 2-21

Both pictures use P = 16 for the blocks and P = 4 for the strips only to keep them readable. In both cuts every node gets the same number of cells, N² / P, so the computing work is identical. The difference is communication:

  • 1-D: 2 messages per node per time step, each a whole column of N cells.
  • 2-D: 4 messages per node per time step, each a shorter edge of k = N / √P cells.

The formulas pretend every node is an interior node with a full set of neighbours. That is the slides' remark "if outer boundaries would not exist". slides 2-23, 2-24

The cost symbols on slide 2-22, as in a network or GPU interconnect: slide 2-22

SymbolMeaningAnalogy
tcompcost of updating one cellone FLOP-ish unit of work
tstartfixed start-up cost of any messagekernel launch or network latency
tcommcost per data item in a message1 / bandwidth

So one message of m items costs tstart + tcomm · m. Full-duplex links mean sending and receiving happen at the same time, so you count only the messages a node sends. Now you have everything you need for Task 2 in lesson 3.

Practice

What is the correct order of the PCAM steps?

P, C, A, M: partitioning, communication, agglomeration, mapping. Slide 2-3.

Which PCAM steps together produce the task dependency graph?

Slide 2-3: partitioning gives the nodes of the graph (tasks), communication gives the edges (data volume).

PCAM partitioning of a convolution on a 640 × 480 image, one task per pixel. How many tasks?

IMGX · IMGY = 640 · 480 = 307 200.

The same image, agglomerated into M = 4 vertical strips. Following slide 2-11, how many pixels in total are communicated between the cores?

2 · (M − 1) = 6 one-way transfers, each one column of IMGY = 480 pixels: 6 · 480 = 2880. Compare with 8 · 640 · 480 ≈ 2.5 million before agglomeration.

In the task-parallel game loop, what are the barriers for?

A barrier holds every task until all tasks reach it, so all four finish frame n before any starts frame n + 1. Slide 2-14.

Mergesort splits the array in half, sorts both halves recursively, then merges them. Which pattern is this?

Slides 2-17 to 2-19 use mergesort as the D2 example: recursive split, solve, merge.

An N × N matrix is cut into horizontal bands, one per node. Which pattern is this?

Regular data (a matrix) split along a dimension: D3. Slide 2-20.

In the heat diffusion problem, how many neighbouring cells does each cell's update read?

Four: up, down, left and right (slide 2-20). The convolution example used eight, because of its 3 × 3 kernel.

N = 120 cells per side, P = 4 nodes, 1-D strips. How many cells does each node update per time step?

N² / P = 14 400 / 4 = 3600. The strip is k = 30 columns wide and 120 rows tall.

Now N = 120 and P = 16 with a 2-D split. How many cells long is each border message?

k = N / √P = 120 / 4 = 30. A 1-D split would send columns of N = 120 cells instead, but only 2 of them rather than 4.

Starting any message is very expensive, but each extra data item is nearly free. Which split should you expect to win?

A large tstart favours fewer messages: 1-D sends 2 per node, 2-D sends 4. Task 2 in lesson 3 turns this into an exact inequality.
